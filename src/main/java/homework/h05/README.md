## Відкрита дискусія

### 1. Навіщо масив, якщо можна завести сто окремих змінних?

Масив дозволяє зберігати багато значень одного типу під одним ім'ям. Замість створення великої кількості окремих змінних можна використовувати індекси та цикли для роботи з усіма елементами. Це робить код коротшим, зрозумілішим і зручнішим для обробки даних.

### 2. Що таке індекс і чому програма падає з «index out of bounds»?

Індекс — це номер елемента в масиві. У Java індексація починається з нуля, тому в масиві з 5 елементів індекси будуть від 0 до 4. Помилка `index out of bounds` виникає, коли програма намагається звернутися до елемента за межами масиву.

### 3. Чому розмір звичайного масиву не можна змінити після створення?

У Java розмір масиву визначається під час його створення і надалі не змінюється. Якщо потрібно зберігати більше або менше елементів, можна створити новий масив і скопіювати до нього потрібні дані або використати `ArrayList`, розмір якого може змінюватися.

### 4. Чому прохід по рядку 2D-масиву швидший за прохід по колонці?

У Java двовимірний масив фактично складається з окремих масивів-рядків. Елементи одного рядка розташовані послідовно, тому процесор може ефективніше отримувати їх із пам'яті. Під час проходу по колонці доступ до елементів відбувається через різні рядки, що може бути менш ефективним.

### 5. Чому масиви нумеруються з нуля, а не з одиниці?

Індекс у масиві вказує на зміщення від початку масиву. Перший елемент має зміщення 0, другий — 1 і так далі. Такий підхід спрощує обчислення адрес елементів і широко використовується в мовах програмування, зокрема в Java.

### 6. Чому додати елемент у кінець масиву дешево, а на початок — дорого?

Звичайний масив у Java має фіксований розмір. Щоб додати елемент, потрібно створити новий масив більшого розміру та скопіювати дані. Якщо вставляти елемент на початок, усі наявні елементи також потрібно змістити вправо. Для частих вставок зручніше використовувати `ArrayList`, хоча вставлення на початок теж потребує переміщення елементів.
